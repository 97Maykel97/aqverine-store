# Схема базы данных AQVERINE

Источник схемы — `prisma/schema.prisma`; SQL-миграции — `prisma/migrations/20261029_init/migration.sql` и `prisma/migrations/20261030_cart_merge_events/migration.sql`. Они подготовлены, но **не применены**: в рабочем окружении пока нет `DATABASE_URL` и доступного PostgreSQL. Текущий frontend продолжает читать mock-каталог и гостевую корзину.

## Модели

| Модель / таблица | Поля и связи | Ключевые ограничения |
| --- | --- | --- |
| `User` / `users` | `id` — UUID пользователя Supabase Auth; `role`, timestamps; связи с профилем, корзиной и заказами | Роль `user` по умолчанию, `admin` назначается только доверенным серверным процессом. Прямого FK на `auth.users` нет: создание локальной строки следует за проверенной сессией Supabase. |
| `Profile` / `profiles` | `userId` одновременно PK и FK; имя, телефон, timestamps | Один профиль на пользователя. Email берётся из Supabase Auth, чтобы не дублировать источник истины. |
| `Product` / `products` | `slug`, название, описание, категория, состав, уход, базовая цена, валюта, статус, время архивации | Уникальный lowercase slug; положительная цена; `draft`, `published`, `archived`. Публикация без варианта запрещается доменным сервисом на следующем этапе. |
| `ProductVariant` / `product_variants` | `productId`, SKU, цвет, размер, необязательная цена-замена, остаток, активность | Уникальные SKU и `(productId, color, size)`; остаток ≥ 0; цена-замена > 0. |
| `ProductImage` / `product_images` | `productId`, цвет, `localPath` либо `storageKey`, alt-текст, порядок | Ровно один источник изображения; уникальный Storage key; начальный каталог использует локальные файлы до подключения Supabase Storage. |
| `Cart` / `carts` | `userId`, timestamps; позиции | Одна серверная корзина на пользователя. Гостевая корзина остаётся в `localStorage`. |
| `CartItem` / `cart_items` | `cartId`, `variantId`, количество | Уникальная пара `(cartId, variantId)` и количество > 0. Цена не сохраняется как авторитетная: при заказе сервер заново читает актуальную цену варианта и остаток. |
| `CartMergeEvent` / `cart_merge_events` | `cartId`, `mergeKey`, время объединения | Уникальная пара `(cartId, mergeKey)` не позволяет повторному запросу добавить гостевые позиции второй раз. Записи удаляются вместе с корзиной; таблица закрыта RLS без клиентских политик. |
| `Order` / `orders` | UUID, уникальный номер, `userId`, статус, subtotal/total, валюта, snapshot контактов и согласия, timestamps | Положительные суммы в minor units; индекс по пользователю/дате и статусу/дате. Статус `paid` устанавливает только обработчик подтверждённого webhook. |
| `OrderItem` / `order_items` | `orderId`, необязательные ссылки на товар/вариант, snapshot названия, SKU, цвета, размера, цены, количества и суммы строки | Положительные цена, количество и сумма. При удалении товара или варианта ссылки обнуляются, но snapshot остаётся. |
| `Payment` / `payments` | `orderId`, провайдер, ID провайдера, idempotency key, сумма, валюта, статус, timestamps | Уникальные idempotency key и `(provider, providerPaymentId)`; сумма > 0. Данные карты и CVV отсутствуют. |
| `PaymentWebhookEvent` / `payment_webhook_events` | Провайдер, ID и тип события, необязательный `paymentId`, статус, hash payload, время получения/обработки | Уникальная пара `(provider, providerEventId)` для защиты от повторной доставки. Сырой payload и платёжные реквизиты не хранятся. |

Таблицы и столбцы используют `snake_case`. Для внешних ключей и основных выборок предусмотрены индексы. Все денежные поля — целые minor units: для текущей валюты USD `2900` означает `$29`; floating-point для денег не используется. SQL-миграция дополнительно накладывает CHECK-ограничения и включает RLS без клиентских политик на всех таблицах. Это закрывает прямой доступ браузерных ролей Supabase; сервер всё равно обязан проверять сессию и роль при каждом обращении.

## Миграция и начальное заполнение

После настройки прямого подключения PostgreSQL через `DATABASE_URL` в локальном `.env.local` выполните:

```bash
npm run db:validate
npm run db:deploy
npm run db:seed
```

`npm run db:migrate` предназначен для разработки следующих миграций; `npm run db:generate` обновляет типизированный Prisma Client. Seed идемпотентно создаёт шесть товаров и варианты из текущего mock-каталога, не перезаписывая уже отредактированные товары при повторном запуске. Для production seed запускается только как отдельное осознанное действие, а не автоматически при deploy.

Серверная корзина принимает UUID варианта для изменения количества. При объединении гостевая корзина передаёт текущие SKU и устойчивый `mergeKey` в UUID-формате; сервер разрешает SKU в UUID вариантов и складывает количества по варианту в транзакции, ограничивая их актуальным остатком. Повтор с тем же ключом не меняет корзину. После успешного объединения клиент должен удалить локальную гостевую корзину; подключение этого поведения к UI ещё не выполнено.

Схема не заменяет доменные проверки: перед публикацией товара, изменением корзины и созданием заказа сервер проверяет варианты, остатки, цены, права доступа и переходы статусов внутри транзакций. Изменение схемы требует новой Prisma migration и обновления этого документа.
