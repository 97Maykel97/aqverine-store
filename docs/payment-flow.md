# Платёжный поток

```text
Checkout
-> сервер создаёт Order со статусом pending_payment
-> PaymentProvider создаёт платёж
-> пользователь переходит на защищённую страницу оплаты
-> провайдер отправляет webhook
-> сервер проверяет подпись
-> сервер идемпотентно обновляет Payment и Order
-> пользователь видит страницу успешной или неуспешной оплаты
```

Провайдерские ключи, webhook secret, PAN и CVV остаются только на сервере. Невалидная подпись получает `401` или `403`. Повторная доставка события не создаёт новый заказ и не повторяет переход состояния. Только подтверждённый webhook может установить `paid`; `cancelled` и `failed` не могут это сделать.
