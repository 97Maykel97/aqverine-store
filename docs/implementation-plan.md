# План реализации AQVERINE

1. Подготовить оболочку приложения: общий layout, адаптивные header и footer, навигацию, типографику, токены из `Design.md` и общие состояния loading, error, empty и success.
2. Реализовать главную страницу с hero-блоком, категориями, популярными товарами, преимуществами и переходами в каталог и drawer-корзину.
3. Реализовать каталог: сетку товаров, фильтрацию по категориям, загрузку изображений и состояния пустого результата и ошибки.
4. Реализовать страницу товара: галерею, сведения о товаре, выбор цвета и размера, остаток, количество, добавление в корзину и похожие товары.
5. Реализовать клиентскую корзину: счётчик, адаптивный drawer, гостевую корзину в `localStorage`, изменение количества, итоговую сумму, удаление позиций и переход к checkout.
6. Реализовать интерфейсы авторизации, личного кабинета и checkout: регистрацию, вход, восстановление пароля, профиль, историю заказов, форму checkout, согласие, результат оплаты и доступную валидацию.
7. Реализовать защищённые интерфейсы `/aqverine-control`: вход, управление товарами, вариантами, фотографиями, остатками и операционными статусами заказов.
8. Добавить metadata, Open Graph, `sitemap`, `robots` и оптимизированные адаптивные изображения публичных страниц.
9. Описать Prisma schema и создать миграции PostgreSQL для пользователей, профилей, каталога, вариантов, изображений, корзин, заказов, платежей и webhook-событий; добавить начальное заполнение каталога.
10. Реализовать Supabase Auth и серверную авторизацию: защищённые cookies сессий, роли покупателя и администратора, защиту account/admin-маршрутов, восстановление пароля и объединение гостевой и серверной корзин.
11. Реализовать серверные API и доменную логику каталога, корзины, проверки остатка, создания заказа со snapshot позиций, Supabase Storage и admin CRUD с Zod-валидацией.
12. Реализовать интерфейс `PaymentProvider`, создание карточного платежа, подписанные идемпотентные webhooks, переходы статусов платежа и заказа, rate limiting и безопасную обработку ошибок.
13. Добавить тесты объединения корзин, остатков, snapshot заказа, авторизации, идемпотентности payment webhook и критичных API-ошибок; выполнить lint, typecheck, тесты, production build и browser-проверку.

Текущий статус: пункты 1–5 выполнены на mock-каталоге. По пункту 6 формы авторизации подключены к серверным обработчикам, защищённый кабинет использует API профиля и истории заказов, но checkout ждёт создания заказа и оплаты. По пункту 7 `/aqverine-control` проверяет роль `admin` на сервере, но CRUD ещё не реализован. Пункт 8 выполнен для публичных страниц. По пункту 9 подготовлены Prisma schema, миграция и seed; применение к PostgreSQL ожидает `DATABASE_URL`. По пункту 10 готовы Supabase Auth, email callback, cookie-сессия, роли и защищённые маршруты; объединение корзин после входа ждёт серверную корзину. Пункты 11–12 ещё не реализованы в базовой ветке; серверные API каталога и корзины подготовлены в отдельных feature-ветках. По пункту 13 frontend- и компонентные тесты готовы, живая backend-интеграция ожидает доступные Supabase и PostgreSQL.
