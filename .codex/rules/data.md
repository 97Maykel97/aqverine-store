# Правила данных

- Изменения БД требуют изменения Prisma schema и сгенерированных migrations.
- Перед изменением схемы читайте `docs/db-schema.md`, затем обновляйте его и `docs/progress.md`.
- Храните деньги целыми minor units; никогда не используйте floating-point.
- Каждый product variant — это одна комбинация цвета и размера с собственным остатком.
- Не создавайте товары без обязательных variants и не допускайте количество в корзине выше доступного остатка.
- Объединяйте одинаковые CartItem по `variantId`; гостевые корзины храните в `localStorage`, авторизованные — на сервере.
- При входе объединяйте гостевую и авторизованную корзины в пределах актуального остатка.
- В каждом `OrderItem` храните неизменяемые snapshots названия, цены, цвета и размера.
- Архивируйте товары или сохраняйте ссылки, чтобы удаление из каталога не портило историю заказов.
- Повторно валидируйте цену, остатки, итоги и авторизацию в transaction при checkout и изменении остатков.
- Для ревью схемы, SQL и миграций используйте `.agents/skills/database-review/SKILL.md`.
- Не изменяйте уже созданные миграции: новое ограничение или индекс оформляйте следующей миграцией. Перед выпуском проверяйте влияние на существующие строки и план отката.
- Проверяйте `PK`, `FK`, `UNIQUE`, `CHECK`, `ON DELETE`, индексы для выборок и внешних ключей; сверяйте Prisma schema с ручным SQL в миграциях.
- Держите транзакции короткими; внешние API не вызывайте под блокировкой БД. Для конкурентного изменения остатков используйте атомарное условное обновление или эквивалентную защиту.
- Не используйте `prisma db push` или reset для общих и production-баз. Применяйте версионированные миграции через `db:deploy` после проверки окружения.
