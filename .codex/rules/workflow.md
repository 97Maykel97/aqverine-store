# Правила рабочего процесса

- Перед редактированием читайте правила, требуемые `AGENTS.md`.
- Перед существенными изменениями изучайте репозиторий и документацию.
- Держите зависимости минимальными и обоснованными; не добавляйте production dependencies без причины.
- Для нового поведения создавайте только критические unit-, integration-, component- и E2E-тесты, соответствующие его рискам. После первого создания тестового файла агент не вправе самостоятельно изменять или удалять его, ослаблять проверки, обновлять snapshots/fixtures либо исключать тест из запуска. На последующих задачах существующие тесты можно только запускать для верификации. Если тест падает, сначала исправляйте код приложения; если сам тест стал некорректным, объясните причину и запросите явное разрешение пользователя до любого изменения теста. Новые тестовые файлы для нового функционала разрешены.
- При необходимости обновляйте архитектурную, database, payment-flow и progress документацию.
- Всегда обновляйте `docs/progress.md` после задачи; при изменении БД обновляйте `docs/db-schema.md`.
- Перед передачей существенных изменений запускайте lint, typecheck, tests и build; для интерфейса используйте browser verification.
- Если коммит запрошен, используйте понятные scoped commits; не коммитьте secrets и локальные generated artifacts.
